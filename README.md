# Fast Arrival / Gaon Auto

Production-grade rural ride negotiation and live tracking system built with React Native (Expo SDK 51), MapLibre React Native, OpenRouteService, and Node.js / Socket.IO / MongoDB.

---

## 1. System Architecture

```
                                +-----------------------------------+
                                |   Admin Control Dashboard (Web)   |
                                |   - Driver Document Review        |
                                |   - Manual Verification / Audit   |
                                +-----------------+-----------------+
                                                  |
+----------------------+                          | REST / Socket.IO
| Phone A: Passenger   |                          v
| - Real Hardware GPS  | <===========> +------------------------------------+ <===========> +----------------------+
| - MapLibre Tiles     | REST & Socket | Fast Arrival Backend (Node 20/ESM) | REST & Socket | Phone B: Driver      |
| - Custom Bids & Trip |               | - Express 4 & Socket.IO            |               | - Real Hardware GPS  |
| - Mutual Cash Flow   |               | - MongoDB (2dsphere Driver Geo)    |               | - Foreground Service |
+----------------------+               | - ORS Routing (Driving-Car)        |               | - Trip OTP Entry     |
                                       +------------------------------------+               +----------------------+
```

## 3. Development Startup Procedure

### Step 1: Start Backend API & Realtime Server
```bash
cd services/api
npm run build
node dist/server.js
# Verified at http://<LAN_IP>:5050/health -> {"status":"healthy","service":"gaon-auto-api"}
```

### Step 2: Start Admin Web Dashboard
```bash
cd apps/admin
npm run dev
# Dashboard accessible at http://<LAN_IP>:5173
```

### Step 3: Start Mobile JavaScript Development Client (Metro)
Ensure both physical phones and development machine are connected to the same Wi-Fi network:
```bash
cd apps/mobile
npx expo start --dev-client --host lan
```
* Note: For remote testing across cellular/mobile data, run:
```bash
npx expo start --dev-client --tunnel
```

## 4. Two-Physical-Phone Certification Workflow

### 1. Installation
Install the development client `.apk` generated by EAS Build (`apps/mobile/gaon-auto-dev.apk`) on **Phone A** and **Phone B**.

### 2. Passenger Onboarding (Phone A)
1. Open Gaon Auto on Phone A.
2. Select **Passenger** role. Enter phone number and authenticate with SMS OTP.
3. Grant **Location Permission** (`ACCESS_FINE_LOCATION`).
4. Confirm MapLibre loads street tiles smoothly with hardware GPS blue dot.

### 3. Driver Onboarding & Admin Review (Phone B)
1. Open Gaon Auto on Phone B.
2. Select **Driver** role. Enter distinct phone number and authenticate with OTP.
3. Enter Full Name, Driving Licence Number, and Vehicle Registration Number.
4. Tap **Submit Application**. Status transitions to `PENDING_VERIFICATION`.
5. Open Admin Dashboard on laptop (`http://<LAN_IP>:5173`) -> Click **Drivers** -> Review Phone B's details -> Click **Approve**.
6. On Phone B, tap **Check Status** (or restart app). Status transitions to `APPROVED`.
7. Toggle duty status to **ONLINE**. Verify persistent Android Foreground Service notification appears.

### 4. Booking & Custom Fare Negotiation
1. Phone A: Select pickup and destination landmarks. Tap **Find Auto**.
2. Nearby driver discovery searches dynamically (3km -> 5km -> 7km -> 10km).
3. Phone B receives live ride request card.
4. Phone B inputs custom fare (e.g. ₹60) and ETA (e.g. 5 min) -> Taps **Send Offer**.
5. Phone A receives offer card -> Taps **Accept & Book**. Backend locks driver atomically.

### 5. Live Tracking & ORS Route Recalculation
1. Phone A renders road route polyline from Driver GPS to Pickup spot.
2. Physically move Phone B:
   - Driver Rickshaw marker moves smoothly with compass heading on Phone A.
   - Route recalculates only when crossing the 150-meter threshold (saving ORS quota).
   - In-memory 60-second coordinate cache eliminates duplicate backend requests.

### 6. Driver Arrival & Trip OTP
1. Driver approaches pickup spot and taps **I Have Arrived**.
2. Passenger Phone A displays secure 4-digit Trip OTP.
3. Driver Phone B inputs OTP:
   - Incorrect OTP triggers server rejection (`INVALID_OTP`).
   - Correct OTP starts trip (`RIDE_STARTED`).
4. Route flips automatically from Driver position toward Destination.

### 7. Background & Screen-Lock Location Stream
1. On Phone B during active ride, press Home button or Lock Screen.
2. Walk/drive 100 meters.
3. Phone A confirms continuous vehicle movement reception without stalling.

### 8. Ride Completion & Mutual Payment
1. Phone B reaches destination -> Taps **Complete Ride**.
2. Phone A taps **I Have Paid (Cash)**.
3. Phone B taps **Confirm Payment Received**.
4. Phone A submits star rating and feedback for Driver.
5. Verify matching `rideId` appears across Passenger History, Driver History, and Admin Dashboard.
